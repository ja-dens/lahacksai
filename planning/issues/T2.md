## Outcome

Connect verified Photon beta ingress and private delivery to the v2 application boundary, persistent history, and private outbox.

## Owner and files

Owner role A; preserve current GitHub assignees. src/adapters/photon.py and transport checks. Live transport is not implemented by the local queued-outbox demo.

## Actionables

- [ ] Normalize incoming provider events into IncomingMessage using actual T1 payloads: stable source IDs, sender, timezone-aware timestamp, direction, content kind, text, reply reference, and supported media.
- [ ] Authenticate incoming webhooks/events and distinguish actual stickers from ordinary photos.
- [ ] Fetch/decode the verified static format, enforce media limits, and retain source identity plus content hash; the initial local target format is PNG, not a claim of all Photon sticker-format support.
- [ ] Feed ordinary messages into longer database history without requesting an interpretation. Incoming sticker events in enabled chats trigger automatically; unsupported media takes an honest fallback path.
- [ ] Drain pending private outbox records using enrollment-controlled destinations. Mark delivered only after the chosen provider's actual acknowledgment, and distinguish API acceptance from phone-delivery evidence.
- [ ] Coordinate retry, idempotency, late/out-of-order events, and assistant-originated events with C. Deduplicate source events, not every occurrence of the same image.
- [ ] Provide sanitized fixed-response and replay examples for integration.

## Acceptance evidence

- [ ] A real incoming sticker yields the agreed internal record.
- [ ] A fixed explanation reaches the correct private thread.
- [ ] Retrying one source event does not cause a second send, while two distinct sends of the same sticker are both processed.
- [ ] Group context and another recipient's private destination cannot be selected by model output.

## Handoff

No separate AI interface is required of the recipient. Record the exact beta channel/line, supported media, auth setup, and observed send semantics. Do not claim distributed exactly-once delivery from the current single-process prototype.
